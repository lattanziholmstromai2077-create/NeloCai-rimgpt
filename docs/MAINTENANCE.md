# 日常维护

1. 从 [项目状态](PROJECT_STATE.md) 对齐当前基线。运行 `git status --short --branch`，保护现有修改。
2. 用故障或改进模板记录需求。常规改动从默认分支建立 `fix/<主题>` 或 `feat/<主题>`。小型明确文档变动可直接走默认分支。
3. 复现并定位根因，按实际接口做最小修改。守住现有依赖和加载布局。
4. 按 [验证清单](../tests/README.md) 暂存构建和验证，记录实际结果、影响范围、回退和待办。
5. 更新 [项目状态](PROJECT_STATE.md) 和 [变更记录](CHANGELOG.md)，必要时补事故或决策记录。审查暂存差异，提交并推送分支，需要时合并。
6. 完成适用的功能验证并记录实际覆盖范围后，可以给维护基线打标签。当前基线版本见 [项目状态](PROJECT_STATE.md)。
